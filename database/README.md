# Создание БД Neura

Для новой пустой PostgreSQL 16+. Скрипты запускаются один раз, без удаления существующих таблиц. При конфликте имён транзакция отменяется. Не запускайте их в общей базе другого приложения.

1. Подключитесь в pgAdmin к служебной БД `postgres` под администратором. Отдельной командой вне транзакции выполните:

```sql
CREATE DATABASE neura;
```

2. Откройте Query Tool уже для базы `neura`. Выполните весь `001_initial.sql`, затем `002_runtime_role.sql`. Владелец схемы должен отличаться от `neura_app`.
3. В psql подключитесь к `neura` как администратор и задайте пароль интерактивно:

```text
\password neura_app
```

В pgAdmin пароль также можно задать в свойствах Login/Group Roles → neura_app → Definition. Не сохраняйте пароль в SQL-файлах или Git.

Альтернативный запуск файлов через psql из папки проекта:

```powershell
psql -h localhost -U postgres -d neura -v ON_ERROR_STOP=1 -f database/001_initial.sql
psql -h localhost -U postgres -d neura -v ON_ERROR_STOP=1 -f database/002_runtime_role.sql
```

## Что обеспечивает схема

Аккаунты, хеши сессий и одноразовых токенов, карточки участников, явные разрешения, наблюдения, версии отчётов, закрытые файловые ссылки, согласия и журнал доступа. Наблюдения хранят данные текущих игр и анкет в JSONB; сервер должен проверять их структуру и лимит размера. Автор и владелец обязательны. Удаление аккаунта с зависимыми данными запрещено до явного удаления или передачи этих данных.

`neura_app` не владеет таблицами и не может менять схему или редактировать журнал. Но эта серверная роль имеет доступ к данным всех пользователей: изоляция пользователей и проверка разрешений будут реализованы в API, RLS в этой миграции не настроен. Доступ `contribute` предполагает чтение и добавление наблюдений; ограниченное назначение педагогу требует отдельного механизма заданий перед включением такого сценария.

## Что ещё должен реализовать бэкенд

Argon2id для паролей; криптографически случайные токены и хранение только SHA-256 их значений; атомарное одноразовое погашение токенов; HttpOnly/Secure cookies; CSRF; лимиты входа и отправки писем; проверку владельца/разрешений каждого запроса, включая отчёты и файлы; отзыв сессий; валидацию JSON; запись аудита; очистку истёкших токенов; удаление файлов из хранилища при удалении записей. Сохранение изменений наблюдения должно проверять revision, чтобы не перезаписывать параллельные изменения. Отчёт хранит снимок содержимого и номер исходной ревизии.

MFA, приглашения и восстановление MFA требуют отдельной миграции после выбора библиотеки авторизации. Скрипты сами по себе не включают шифрование дисков, TLS, резервное копирование или защиту публичного сервера. Настройте их на уровне инфраструктуры перед использованием реальных данных. БД доступна только бэкенду; не открывайте порт 5432 всему интернету. Пароль БД никогда не помещается в переменные VITE_*.

## Данные для дальнейшего подключения

Сообщите версию PostgreSQL, host, port, имя БД, имя серверной роли, локальное или удалённое размещение, требования SSL и путь к CA-сертификату при необходимости. Пароль храните локально в игнорируемом Git файле окружения бэкенда; в чат отправлять его не нужно. При подключении подготовим этот файл и проверим, что он исключён из Git. Для локальной установки типичные значения: localhost:5432, база neura, пользователь neura_app.

Справочник PostgreSQL по ограничениям: https://www.postgresql.org/docs/16/ddl-constraints.html

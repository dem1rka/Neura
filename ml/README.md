# Исследовательская модель Neura

Из папки проекта выполните `npm.cmd run ml:train`. Нужны Node с поддержкой `--env-file`, Python 3.11, зависимости сервера (`npm ci --prefix server` при свежем клонировании), настроенный `server/.env` и доступная PostgreSQL со схемой Neura. Запускать HTTP-серверы не требуется. Первый запуск устанавливает закреплённые версии библиотек и скачивает открытые таблицы. Следующие используют локальный кэш. Несовпадение SHA-256 или ошибка БД останавливает команду.

| Результат | Путь относительно проекта |
|---|---|
| Отчёт и таблицы по центрам | ml/results/report.md |
| Все метрики, выбор кандидатов и порогов по разбиениям, количества отобранных строк и хеши | ml/results/metrics.json |
| Сериализованная модель с порядком полей и порогом | ml/results/srs_model.joblib |
| Базовая модель по сумме SRS, проверенная на ABIDE I Yale | ml/results/srs_total_model.joblib |
| Семейная демомодель и результат проверки на синтетике | ml/results/family_synthetic_demo.joblib и ml/results/family_synthetic_demo.json |
| Словарь и происхождение полей | ml/FEATURES.md |
| Закреплённые URL и SHA-256 | ml/sources.json |
| Публичная производная выборка и отложенные прогнозы по участникам | ml/cache/clinical.csv и ml/cache/held_out.csv |
| Приватная локальная выгрузка | ml/private/neura.json |
| Сгенерированные пары анкеты и игры | ml/cache/synthetic.json |

Пример использования на **вымышленных** пяти значениях SRS из комплекта:

```powershell
.\ml\.venv\Scripts\python.exe ml/score.py ml/example-srs.json
```

Команда печатает исследовательский балл соответствия группе ABIDE и положение относительно порога. Данные проекта используют другую анкету. Автоматической подстановки её ответов вместо SRS нет.

Для базовой модели укажите `--total` и JSON с единственным полем `srs_total_raw`, например `{"srs_total_raw":49}`.

## Отбор данных и воспроизводимость

Основной эксперимент использует пять поперечных выборок ABIDE II с детской формой, заполненной родителем, валидной суммой пяти сырых шкал и обеими диагностическими группами. Включались участники, которым при сканировании исполнилось 3 года и ещё не исполнилось 12. TCD исключён из-за отбора части контроля по признаку модели. Продольные измерения не входят. Этап сопоставления не объединяет детей из разных баз. Для отдельной внешней проверки простой модели по сумме взят центр Yale из ABIDE I, отсутствующий в обучении. Базовая частота класса и регрессия по сумме используют те же внешние разбиения, что и основная модель. Подробные исходные протоколы доступны у [ABIDE II](https://fcon_1000.projects.nitrc.org/indi/abide/abide_II.html) и [ABIDE I PCP](https://preprocessed-connectomes-project.org/abide/download.html).

Для игры рассматривался и открытый DREAM. В нём записаны занятия с роботом у детей с РАС. Нет контрольной группы, а задания отличаются от Neura. Использовать эту базу для оценки распознавания РАС по игре Neura было бы некорректно. [Публикация авторов DREAM](https://pmc.ncbi.nlm.nih.gov/articles/PMC7444515/).

## Обучение семейной модели по паре «анкета + игра»

В одном назначении специалиста должны быть завершены оба семейных задания. Импорт независимых меток поддерживает локальный CSV `ml/private/labels.csv` с колонками `participant,assessment,asd`. Первые две колонки берутся из псевдонимизированной выгрузки, последняя — независимо установленная группа 0 или 1. Синтетические строки и известные демо-аккаунты исключаются. Происхождение остальных обследований и меток должен подтвердить составитель файла. Не заполняйте метки группами, вычисленными по самой анкете.

При наличии меток та же команда обучает логистическую регрессию по шести категориальным ответам. Каждому ребёнку соответствует одно обследование, выбранное детерминированно по идентификатору без учёта ответов. Отложенные прогнозы строятся по разным детям, метрики появляются в отчёте, артефакт — в `ml/private/family_model.joblib`. При отсутствии пар или достаточного числа меток отчёт показывает причину. Эта модель относится только к трёхшаговым семейным заданиям. Для подробной игры из восьми сцен и рабочей анкеты понадобится сохранять общий идентификатор обследования.

## Проверки

```powershell
node --test ml/test_export.mjs
.\ml\.venv\Scripts\python.exe -m unittest discover -s ml -p test_pipeline.py
```

Проверки охватывают происхождение полей, обработку пропусков, исключение свободного текста, валидность входа модели, воспроизводимость генератора, полноту отложенных прогнозов, сопоставление семейных заданий и разделение детей. Локальный ключ псевдонимизации используется повторно для последующих выгрузок. Ключ, индивидуальные записи и кэш исключены из Git.
